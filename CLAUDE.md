# Инструкции для работы над проектом

## Главный документ

Полное техническое задание и план работ — в файле `PROMPT.md` в корне репозитория.
Прочитай его перед началом любой задачи. Всё, что там написано, обязательно к исполнению.

## Как вести работу

1. **Строго по этапам** из раздела 13 файла `PROMPT.md`. Один запрос — один этап.
   Не забегай вперёд и не делай то, о чём не просили.
2. **Останавливайся после каждого этапа.** Покажи, что сделано, и жди подтверждения.
3. **Объясняй решения простыми словами.** Автор проекта — начинающий разработчик,
   которому предстоит защищать этот код на собеседовании. Перед каждым нетривиальным
   куском коротко скажи: какую задачу он решает, какие были варианты, почему выбран этот.
   Если применяешь приём, которого раньше в проекте не было, поясни его.
4. **Не молчи о проблемах.** Если требование из `PROMPT.md` кажется ошибочным или
   невыполнимым — скажи прямо, а не обходи молча.
5. **Спрашивай при неоднозначности** вместо того, чтобы додумывать.

## Технические правила

- Язык: Go. Python и другие языки не использовать нигде, включая вспомогательные сервисы.
- Библиотеки только из раздела 4 `PROMPT.md`. Нужна другая — сначала предложи и обоснуй.
- Код, комментарии, имена, тексты ошибок, сообщения коммитов — на английском.
- README и диаграммы — на русском.
- Никаких `panic` в рабочем коде.
- Никаких ORM и DI-контейнеров на рефлексии.
- Деньги — целое число копеек, никаких `float`.

## Перед тем как сказать «готово»

Прогони и убедись, что проходит:

```
make lint
make test
```

Если команды ещё нет в `Makefile` — добавь её в рамках текущего этапа.

## Работа с гитом

- Коммит делается в конце этапа, не раньше.
- Сообщение коммита на английском, в повелительном наклонении: `add order state machine`.
- Не коммить сгенерированные бинарники, `.env` с секретами, содержимое `vendor/`.

## Чего не делать

- Не переписывать уже принятые архитектурные решения без обсуждения.
- Не добавлять Kafka, Redis и другую инфраструктуру: в `PROMPT.md` объяснено, почему их нет.
- Не расширять scope. Список исключений — раздел 15 `PROMPT.md`.
- Не оставлять `TODO` в коде вместо реализации. Если что-то не сделано, скажи об этом словами.
